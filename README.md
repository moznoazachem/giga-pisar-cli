# Гига Писарь

Распознавание русской речи в командной строке. Быстро, на процессоре, без интернета.

```
$ pisar запись.ogg
Так, значит, я могу уже говорить, да? Ну, буду говорить всякую фигню или как.
```

Под капотом — [GigaAM v3](https://github.com/salute-developers/GigaAM) от команды
GigaChat, лучшая на сегодня открытая модель для русского языка. Она уже переведена
в формат ONNX и сжата до int8, поэтому работает на обычном сервере без видеокарты
и весит 309 МБ вместо гигабайта (204 МБ в архиве).

*Russian speech-to-text CLI powered by GigaAM v3 (ONNX int8, CPU-only, offline).*

## Зачем, если есть сама GigaAM

Библиотека умеет ровно одно: взять правильно подготовленный звук и выдать текст.
Всё остальное приходится делать самому. Писарь берёт это на себя:

- **любой формат** — ogg, m4a, mp3, wav; всё, что понимает ffmpeg;
- **длинные записи** — модель не принимает больше 25 секунд, а Писарь режет запись
  по паузам между фразами, а не посреди слова, и склеивает результат;
- **чистый вывод** — в stdout уходит только текст, все служебные сообщения
  библиотеки перенаправлены в stderr; результат можно сразу пускать по конвейеру;
- **готовые файлы модели** — не нужно ставить torch и экспортировать ONNX самому.

Ничего никуда не отправляется: модель лежит файлом на диске, распознавание идёт
на той же машине.

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/moznoazachem/giga-pisar/main/install.sh | bash
```

Ubuntu 22.04 и 24.04. Ставит окружение в `/opt/giga-pisar`, скачивает модель
из релиза и кладёт команду `pisar` в `/usr/local/bin`.

Другая папка — `bash install.sh ~/giga-pisar`.

## Использование

```bash
pisar запись.ogg                  # один файл
pisar *.m4a                       # несколько
pisar --model-dir ~/model а.wav   # своя папка с моделью
```

Из своей программы удобнее звать подпроцессом — GigaAM тянет за собой torch,
и мешать её окружение с окружением приложения обычно не хочется:

```python
text = subprocess.run(
    ["pisar", path], capture_output=True, text=True, check=True
).stdout.strip()
```

## Сколько работает

Замеры на 2 ядрах Xeon Gold 6448Y, запись 13 секунд:

| Этап | Время |
|---|---|
| загрузка модели | ~4 с |
| само распознавание | ~3 с |

Модель загружается при каждом запуске. Для потока записей выгоднее держать
процесс живым и звать `load_onnx` один раз.

Памяти нужно около 1.5 ГБ на время работы.

## Грабли, на которые мы уже наступили

Собрано не с первого раза — эти четыре вещи стоили нам вечера.

**gigaam из PyPI не подойдёт.** Там лежит 0.1.0 со старым API: функций
`load_onnx` и `infer_onnx`, нужных для модели v3, в ней просто нет.
Ставить только из исходников с GitHub.

**Версии жёстко связаны.** `gigaam` 0.2.0 требует `onnxruntime` ровно 1.23.x,
а тот — `numpy` второй ветки. Более старый onnxruntime с numpy 2 падает прямо
на импорте, с сообщением про `_ARRAY_API not found`.

**Токенизатор живёт отдельно от модели.** При экспорте ONNX в `v3_e2e_rnnt.yaml`
записывается абсолютный путь к файлу токенизатора — с той машины, где экспорт
делали. На любой другой модель падает с `OSError: Not found`. В нашем архиве
путь оставлен заглушкой, а `install.sh` подставляет настоящий.

**Резать по времени нельзя.** Если просто нарезать длинную запись кусками
по 24 секунды, разрез попадёт в середину слова и оно потеряется. Писарь
ищет паузы через `silencedetect` и режет по ним.
